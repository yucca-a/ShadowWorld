# 妥测薇诺娜工作效率修复（2.8.15.0.23 已发布，2026-11-11）

修复已按归属拆开：淬炼制作增强的修复与工作初始化由 `easy_role/winona_easy.lua` 加载 `scripts/winonabuilder2hm.lua`；妥测自身的死亡复活监听问题才由 `easy_other/um_patch.lua` 加载 `scripts/umwinonaworker2hm.lua`。未新增开关；已随 2.8.15.0.23 发布，线上版本、日志和下载包均已核验。

## 实际定位

妥测 6.0.3.9 的 `init/init_character_changes/winona.lua` 仍注册了动作扣饥饿和按饥饿变动更新倍率的回调。使用真正的 `PerformBufferedAction` 验证，砍树仍会消耗 0.2 点饥饿（乘饥饿消耗修正），满饥饿工作量为 1.5、工具消耗为 0.5。整个机制并未消失。

明确复现的问题是：

- `WinonaWorkerStuff` 注册 `hungerdelta` 后没有初次刷新，因此新生成角色在第一次饥饿变化前，工作与耐久倍率都停留在 1。
- 淬炼“薇诺娜制作不再受饥饿值影响”直接移除了 `hungrybuilder`，并把 `TUNING.DSTU.WINONA_WORKER` 改为 false。前者破坏妥测原生采集加速，后者会关闭正式版工作能力。两处都属于淬炼自己的错误处理，现已在角色增强入口修正。
- 妥测死亡回调误写成重新监听 `performaction`，没有正确移除动作扣饥饿回调；需要在变鬼时移除，复活后恢复一份。

`TUNING.DSTU.WINONA_WORKER` 与妥测实际读取的 `UM_CONFIG.WINONAWORKER` 是不同字段。前者被旧兼容代码设为 false，并不能证明妥测的工作机制已关闭。

## 修复范围

`scripts/winonabuilder2hm.lua` 不再关闭妥协的工作开关。所有配置均保留原生 `hungrybuilder` 标签，不再通过删除角色标签实现制作增强；启用妥协工作能力时，让原生采集路由自行工作；“制作不受饥饿影响”只调整服务端和客户端 BUILD 动作，保留其他角色、专属配方和其他模组的特殊制作状态。没有另加或替换 PICK 路由。

初始倍率由淬炼薇诺娜增强入口复用已核对的正式／测试版更新回调补齐，独立于“永不妥协补丁”开关。上游若已初始化则不再调用，未知回调则跳过。原妥测确实缺少首次刷新，但本轮将整合时的初始化安排在淬炼角色增强中，不再把它归入可选妥协补丁。

`scripts/umwinonaworker2hm.lua` 仅修复已核对妥测的死亡复活监听：变鬼时移除工作监听与自身倍率，复活时恢复一份。该部分单独受“永不妥协补丁”控制。

没有重写扣饥饿公式，没有另加扣饥饿监听，没有新增倍率来源。满饥饿／中等／饥饿三个档位仍分别为 1.5／1／0.666 工作量和 0.5／1／1.333 工具消耗。原有动作扣饥饿、0.3 秒冷却、饥饿消耗修正继续由妥测处理。其他模组的倍率来源不受死亡清理影响。

本轮不再额外包装或合并上游 PICK 路由，直接修正淬炼的错误标签／开关处理。

## 未来更新兼容

复用已有 `umcompatguard2hm` 和 `umcompatprofiles2hm`。按源码路径及 Lua 可执行函数指纹识别已核对的倍率更新、扣饥饿、死亡复活回调，不按版本号强制覆盖。

- 核心回调变化或不存在：整项跳过。
- 死亡复活回调变化：跳过生命周期补丁，不替换未知实现。
- 上游已初始化倍率：不再次初始化。
- 上游自行修复初始化和生命周期：初始化不重复执行，生命周期补丁记录为 skipped；采集一直由上游原生路由处理。

生命周期状态记录位于 `TUNING.UM_COMPAT_STATUS2HM.winona_worker`。模拟新上游倍率 1.6，以及上游自行初始化、修复生命周期，均保留上游实现，没有重复倍率或扣饥饿。

## 验证

`tests/run_winona_worker_tests.py` 使用实际妥测闭包与原生倍率组件，检查本地增强与上游补丁分离、双端制作路由、原生采集保持、死亡清理、其他倍率保留、复活去重和未来更新退让。

`tests/run_native_winona_worker.py --case all` 在隔离原生离线专服运行七种场景：妥测、关闭妥协补丁、关闭妥测工作能力、关闭制作增强、关闭淬炼薇诺娜增强、正式版、单开。关闭妥协补丁后，本地制作／初始倍率／快采修复仍须通过；关闭淬炼薇诺娜增强后，上游补丁不擅自初始化角色倍率。真实动作核对三档工作、损耗、扣饥饿与冷却；实际推进原生采集／制作状态完成动作，核对客户端原生制作路由、五次死亡复活事件和角色保存恢复。

测试不修改玩家世界。未执行真实客户端鼠标操作和采集动画的画面验收。
