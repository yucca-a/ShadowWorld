# 穿越世界：持久化事务重写

> 本文记录此前逐次存档版本，供旧事务兼容与回退参考。当前默认实现已改为 [穿越世界快速版](穿越世界快速版_实装说明.md)，不再在每次穿越时保存世界。

日期：2026-11-03。状态：已实装并完成自动测试、独立双层专用服务器验证；同步本地测试模组，尚未发布工坊。正式版本号仍为 2.8.14.96.1。

## 玩家看到的变化

- 保留原有末影箱等跨世界共享容器的“穿越”入口，仍为**双方整箱交换**，不是只把本方物品发过去。
- 使用已有功能时自动启用新机制，无需新增配置。两层服务器必须一起更新、重新载入。
- 交换期间双方容器只读，暂停排序与收集等写入；完成存档和双方确认后解锁。
- “暂停”按钮改为“状态”：查看等待、保存、完成或保护锁定状态，并请求重试通信。模块不再替玩家暂停或恢复服务器。
- 短暂延迟、消息丢失和正常重连由协议自动重试。准备超时会取消并保留原物品；已进入持久化提交的交换持续等待恢复，不按短超时强行回滚。
- 保留格位、堆叠、耐久和物品存档数据；皮肤恢复使用来源世界会话。容器锁定期间暂停腐烂和温度变化，解锁恢复原保鲜倍率。

## 为什么需要重写

旧方案把容器内容临时放在内存字段中，过早删除原物品，以 1.5 秒和 3 秒超时判断成功或恢复。消息处理与超时又使用不同的时间调度。延迟稍高便可能中断，最后确认丢失时还可能出现一侧已接收、另一侧恢复旧物品的结果。

旧代码故障模拟复现：单程 0.8 秒延迟时容易失败；冻结普通游戏计时、让静态消息处理继续后可完成，与“暂停后恢复”现象一致。这是模拟结果，不等同于已经获取用户故障存档并复现。

参考[巨型漩涡](https://dontstarve.huijiwiki.com/wiki/巨型漩涡)并核对本机游戏原生 `worldmigrator`、`shardtransactionsteps`、`itemstore`：可借鉴事务编号、阶段保存和连接恢复。原生物品传送是单向、单件机制，不能直接替代双方整箱交换；底层仍共用跨分片通信队列，因此仅更换 RPC 名称不能解决问题。

## 交换顺序

1. **准备**：发起方锁箱并冻结物品记录，目标方核对容量、物品数据，锁箱并回传自己的记录。此时原物品仍在双方箱内。
2. **第一次同步存档**：双方记录同一事务的提交意图及两份物品记录，使用原生 `ms_save` 协调地面、洞穴存档；只有真实保存回调确认对应阶段已写入，才继续。
3. **应用交换**：先完整恢复收到的物品，再移走原物品并按原格位放入。恢复失败不直接销毁原箱内容；发生放入失败则尝试放回原物品，并锁定记录供排查。
4. **第二次同步存档**：交换后的容器内容与“已应用”阶段一起保存。双方仍不能取物。
5. **确认并解锁**：双方均确认第二次保存后，完成释放握手。重复消息只补发确认，不重复生成物品；最终确认丢失时可从已经保存的阶段继续。

正常路径通常需要两次双层同步存档。初版在本机小型测试世界约 5～6 秒完成交换，事件驱动优化后同场景约 2.8 秒，详见下文。大世界、慢磁盘或高延迟会更慢。每次保存会占用原生回档快照名额；同一事务阶段最多每 10 秒重试请求保存，进入下一阶段可立即请求。暂停游戏时原生存档可能等待游戏恢复，模块不会擅自解除暂停。

## 协议与保护

| 项目 | 实装规则 |
| --- | --- |
| 事务识别 | 发起世界 ID、世界会话、进程启动标识与递增序号组成唯一 ID |
| 持久化 | 世界组件保存阶段、双方物品记录和已结束事务序号；与容器内容同一世界快照保存 |
| 推进与重试 | 请求、消息与保存完成在下一静态帧推进，同帧多事件合并；丢包后保留 1～5 秒定时重试，状态按钮可提前唤醒 |
| 准备超时 | 发起后 20 秒仍未达成准备则持久化取消；对方丢失尚未落盘的准备、且本方也未持久化提交意图时，可安全取消 |
| 提交后断线 | 保持容器锁定，恢复连接后继续；不在未知结果下复制旧物品“补偿” |
| 同时点击 | 同一世界只允许一笔待处理交换；双方同时发起时按世界 ID 确定优先方，合并成一次交换 |
| 多分片 | 在当前已连接的其他世界中排序、轮选；每次只与一个世界交换 |
| 连接校验 | 会话及进程标识、挑战应答；断线和进程变化时清除旧确认，旧进程数据不能覆盖新连接 |
| 分包 | 单块 8 KiB、消息最多 64 块（512 KiB）；每个 0.1 秒发送窗口共用 4 块额度，确认消息优先；物品快照预留消息头空间 |
| 队列边界 | 同阶段未发完的重试合并；最多 32 条待发消息；每对端最多 8 条未完成接收，30 秒过期 |
| 不兼容数据 | 容量/堆叠设置不同、未知预制物、过大记录、不持久化物品、不可替代物品及外部实体关联物品等拒绝交换 |
| 服务器写入保护 | 原生只读容器配合服务端增删/销毁方法保护、排序/收集禁用；锁定时“状态”仍可用 |

## 恢复边界

正常重启从本次事务的有效存档继续，已经应用且持久化的物品不再应用第二次。尚未持久化的物品交换随世界正常回档，再按保存的事务阶段执行。

**单独把某一层回滚到更早的备份，不属于普通断线或重启。** 若两边事务记录对不上，系统保留现有记录并锁定待处理容器，不根据旧消息凭空补发物品。应保留两层存档和日志，检查 `[WorldExchange2hm]` 记录，必要时恢复同一时间的完整双层备份。删除世界组件或直接清空事务字段可能破坏此保护。

若其他模组的物品加载、放入/移除回调报错，系统尽量保留原物品、冻结记录并报告恢复失败；未承诺兼容所有第三方自定义物品、绕过容器 API 的直接改写、损坏存档或底层磁盘写入失败。

## 验证结果

- 初次实装的 Lua 5.1 语法检查及 **574 项自动断言通过**：协议 515 项、引擎适配 59 项。速度优化后的最新测试增至 590 项，见下文。
- 协议测试包含单程 0.8/2/4 秒延迟、各阶段单次丢包、30 组重复/乱序测试、同时点击、断线重连、不同阶段单侧/双侧重启、未保存应用后的崩溃、消耗物品后的旧消息重放、独立旧回档保护。
- 适配测试使用游戏原生序列化与沙箱函数，覆盖分包重组、缓冲上限、旧进程消息、保存阶段匹配、只读保护、皮肤来源、数据冻结及主动注入的恢复失败。
- **真实独立地面/洞穴专用服务器通过**：正常整箱交换；第一次事务存档后强制结束两个进程并重启；第二次事务存档后强制结束并重启。两次恢复均同时注入 2 秒消息延迟及一次最终确认丢失。
- 原生测试检查黄金 17 个、石头 31 个、长矛 42% 耐久、稀疏格位、浆果，以及约 32 KiB 持久化数据分包传输；检查双方解锁，无丢失或重复。测试进程未加入正式玩家世界。
- 正常与两处故障恢复的日志、本机隔离测试服和测试夹具保存在已忽略的 `work/world-exchange-runtime/` 等工作文件中。

自动测试不替代实际玩家打开容器和点击按钮的界面验收。本地测试时应共同重启地面与洞穴，在两边放入不同物品后操作“穿越”，确认整箱互换、格位和数量正确；等待期间“状态”可用且无法取放物品。仅启用一份本模组，避免同时加载工坊版与本地测试版。

## 速度优化（2026-11-03）

初版在每个阶段依赖最多 0.5 秒的轮询等待。现改为收到有效消息、玩家请求、存档回调后在下一静态帧唤醒，保留周期任务用于丢包重试；多个事件合并，避免在 RPC/存储回调内重入状态机。确认消息优先发送，未发出的状态合并为最新值，重复确认不重置重试期限，避免等待存档时反复互相回复。连接状态变化后也不再额外等最多 5 秒才握手。

以下使用相同独立地面/洞穴世界、相同物品与约 32 KiB 持久化记录，各连续交换三轮；从发起到发起方确认完成并解锁，以 `GetStaticTime` 静态帧计时：

| 版本 | 第 1 轮 | 第 2 轮 | 第 3 轮 | 中位数 |
| --- | ---: | ---: | ---: | ---: |
| 优化前 `ba24bfb` | 5.10 秒 | 4.83 秒 | 4.90 秒 | 4.90 秒 |
| 事件驱动优化 | 2.77 秒 | 2.83 秒 | 2.87 秒 | 2.83 秒 |

中位等待缩短约 **42%**。这是本机小型测试世界的三轮对比，不是大存档或公网环境的延迟保证，也没有把仅显示收到物品、尚未解锁的时刻当作完成。两次持久化屏障、校验和容器锁均保留。

原生 `autosaver` 每次保存安排约 1 秒后执行，两次串行保存本身就约有 2 秒调度等待，另需通信与序列化。因此当前方案仍不能承诺旧版的即时体验。直接去掉保存等待会改变崩溃恢复语义；仅独立保存一份事务日志，也不能代替与容器、玩家物品处于同一快照的保证。

优化后的专项测试为 **590 项断言**（协议 518、适配 72），新增同帧事件合并、防重入、统一分包限流、最新确认优先和重复状态不触发应答循环等检查。真实基准夹具为 `tests/native/world_exchange_speed_fixture.lua`，仅用于一次性隔离世界，会覆盖测试箱内容并关闭测试服，不随工坊内容上传。

优化代码还重新通过原生双层故障验证：第一次事务存档后强制结束两个进程，再重启并注入 2 秒消息延迟、丢弃一次最终确认，双方自动完成，格位、数量、耐久和大记录保持正确。

## 文件与回退

- `content/scripts/worldexchangeprotocol2hm.lua`：独立事务状态机。
- `content/scripts/components/worldexchange2hm.lua`：连接、分包、容器和保存适配。
- `content/easy_other/worldexchange.lua`：服务安装、保存完成观察及服务端写入保护。
- `content/easy_other/containersort.lua`：替换旧交换和暂停流程，接入新按钮。
- `content/modmain.lua`：随现有容器功能加载新模块。
- `tests/run_world_exchange_tests.py`：回归入口，两个 Lua 测试文件分别验证协议和适配。

初版开发分支为 `codex/reliable-world-exchange`，优化分支为 `codex/faster-world-exchange`，均包含前一轮离线查看器修复。回退代码前先等待双方交换结束并正常保存；若仍有待处理事务，应连同同一时间的双层存档一起恢复，旧代码不会处理新组件中的未完成事务。
