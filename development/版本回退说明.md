# 版本回退说明

私有仓库：<https://github.com/yucca-a/ShadowWorld>。维护分支：`codex/maintenance`。

## 查看与比较

```powershell
git fetch origin --tags
git tag --list
git log --oneline --decorate
git diff v2.8.14.96 v2.8.14.96.1 -- content/
```

`v2.8.14.97.2` 是当前发布版本；`v2.8.14.97.1` 是弹弓崩溃热修，原版装备权限由当前版修正；`v2.8.14.97` 存在弹弓状态机崩溃，已由该热修修正；`v2.8.14.96.1` 是此前更名发布版本；`v2.8.14.96` 是此前玩法更新；`upstream-v2.8.14.95` 是原始模组基线。前两个历史快照由归档导入，只包含 `content/`，不是完整的旧开发工作区。

## 在独立目录取回旧版本

在仓库根目录执行，目标目录需尚不存在：

```powershell
git config core.autocrlf false
git worktree add --detach ../ShadowWorld-restore-2.8.14.96 v2.8.14.96
```

旧版完整模组位于新目录的 `content/`。这个操作保留当前开发目录和已有提交，可以先测试，再决定是否恢复。将命令最后的标签改为 `upstream-v2.8.14.95` 即可取回最初基线。

前两个历史标签只含原始源码，没有 `.gitattributes`。关闭本仓库的自动换行转换，可以避免 Windows Git 改写旧版文件的行尾，保证与 SHA-256 清单一致。此设置只作用于当前仓库。如果只想导出源码压缩包，可执行：

```powershell
git -c core.autocrlf=false archive --format=zip --output=../ShadowWorld-v2.8.14.96.zip v2.8.14.96 content/
```

## 将旧版玩法恢复为新的维护版本

先提交或另行备份当前改动，确认 `git status --short` 为空，然后在独立分支操作：

```powershell
git config core.autocrlf false
git switch -c codex/rollback-to-2.8.14.96
git restore --source=v2.8.14.96 --staged --worktree -- content/
git diff --cached --stat
git diff --cached -- content/modinfo.lua
```

此时整个 `content/` 与目标版本对应，包括该版本的名称、版本号、配置和文件增删。重新发布前，要整理 `modinfo.lua` 中的名称与维护信息，使用新的版本号，完成相应测试，并编写新的更新日志。保留 `content/LICENSE` 及原作者署名。

测试后正常提交和推送，在评审或确认后合入维护分支。用新的提交记录回退，保留后续问题排查所需的历史；已有发布标签保持原样。

## 工坊与世界存档

Git 回退不会自动更新创意工坊。上传仍使用原条目 **3832182265**，数据目录为所选版本的 `content/`。官方上传器要求版本号与工坊当前版本不同，通常应分配新的版本号，而不是重复上传旧版本号。

Git 管理的是模组代码和资源，不能恢复玩家世界、配置或运行中的存档数据。涉及旧版不兼容的存档结构时，先备份世界，再在测试存档验证。现有存档的配置选择也不会仅因代码回退而自动重置。
